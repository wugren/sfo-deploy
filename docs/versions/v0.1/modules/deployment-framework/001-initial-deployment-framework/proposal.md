## Background and Goal
创建仓库的第一个产品模块：一个 Python 部署框架，每个集群配置是一个自包含目录。框架读取目录中的机器、环境组件与应用元数据，解析每台机器的首选 SSH 地址，按依赖顺序安装数据库等运行环境、获取应用包，并运行配置和控制每个应用所需的脚本。

首个版本应建立一个小而可审计的执行核心，而不是尝试成为完整的集群编排器。它应让所选的配置、主机、环境组件、应用、依赖关系、动作、脚本顺序和结果清晰无歧义。

## Scope

### 范围内
- 一个可作为依赖安装和导入的版本化 Python 包，同时提供通用命令行入口和供项目部署模块绑定的公开 CLI/API 接口。
- 框架公开稳定的 `create_cli(...)` 和 `run(...)` 集成边界。项目中的部署模块引用该包后，显式绑定项目自己的集群配置根目录、可选自定义下载提供方、`file_secrets` 和 `config_secrets`，并导出一个零额外粘合逻辑的命令入口。
- 项目命令从绑定的部署模块位置解析项目内集群配置，不依赖调用命令时的当前工作目录。相对路径继续以所选集群目录或应用目录为基准解析。
- 多个集群配置目录可以在用户选择的配置根目录下共存；每个目录是一个可独立选择的集群。
- 规范的集群目录布局：
  - `cluster.yaml` 记录集群身份、部署执行器的当前/默认区域、默认值，以及应用到机器的分配。
  - `machines.yaml` 记录每台机器的唯一名称、支持的域名、私有 IP、公网 IP、区域、SSH 用户、端口、可选本地 SSH 私钥路径，以及该机器需要部署的环境实例。每个环境实例记录实例名、所用环境脚本定义、版本、参数覆盖、同机环境依赖和权限要求。
  - `environments/<environment-name>/environment.yaml` 是可复用的环境脚本定义，记录数据库、语言运行时或其他基础环境组件的默认参数、权限要求，以及 `check`、`install`、`configure`、`start`、`stop`、`restart` 对应的有序 Python 脚本；该定义本身不选择目标机器，也不以声明式规则代替安装脚本。
  - 环境部署脚本是 `environments/<environment-name>/` 下的 Python `.py` 文件（允许并显式引用 `scripts/` 子目录）；脚本路径不得逃逸该环境目录。一个环境脚本定义可被多台机器分别引用并接收不同的机器级版本和参数。
  - `apps/<app-name>/app.yaml` 记录匹配的应用名称、版本、包哈希与算法、下载提供方、提供方特定的下载信息，以及有序的生命周期脚本映射。
  - 环境/App 定义可声明配置脚本需要的配置密钥名称和模板文件，也可声明要在配置动作前部署到目标机器的文件私钥逻辑名称及目标属性；真实文件路径和值只由项目部署模块绑定。
  - 应用部署脚本是 `apps/<app-name>/` 下的 Python `.py` 文件（允许并显式引用 `scripts/` 子目录）；脚本路径不得逃逸该应用目录。
- 机器名称是稳定的清单身份。域名是元数据/别名，仅在配置显式选择时使用；自动路由使用 IP 字段。
- 地址选择会比较每台机器的区域与配置的执行器/源区域：同区域机器默认使用私有 IP，跨区域机器默认使用公网 IP。CLI 可以覆盖执行器区域，或显式选择已声明的地址类型。缺少必需地址时验证/执行失败关闭，而不是在信任边界上静默回退。
- 每个应用记录分配给哪些命名机器；引用必须在同一集群目录内解析。
- 环境实例只在所属机器的配置中声明，不由环境模板维护机器列表。环境实例的稳定身份是 `<machine-name>/<instance-name>`，同一环境模板可以在同一或不同机器上创建多个独立实例。
- 机器内的环境实例可通过 `depends_on` 引用同机其他环境实例；App 可引用目标机器上的环境实例，也可显式引用其他机器的完整环境实例身份。完整依赖图必须无环，框架按稳定拓扑顺序先执行环境实例，再执行依赖它们的 App。
- 基于主机别名/地址、端口、用户、SSH agent 或本地 SSH 私钥路径，以及严格 known-host 验证的 SSH 连接配置。
- 环境组件的实际操作全部通过 `check`、`install`、`configure`、`start`、`stop` 和 `restart` Python 脚本完成；框架只负责选择、传输、传参、排序、执行和汇总结果。`check` 脚本判断机器配置要求的版本/状态是否已满足，返回满足时框架跳过 `install`，否则执行 `install` 脚本。
- 每个应用为初始动作 `configure`、`deploy`、`start`、`stop` 和 `restart` 维护有序的 Python 脚本列表，相对于该应用的同名目录解析；非 `.py` 生命周期脚本被拒绝。
- 环境组件可声明供 Python 脚本使用的包下载信息；声明包时复用同一下载提供方与强制哈希校验契约。不声明包时，`install.py` 可调用目标系统已有的包管理能力。框架不根据机器配置自动生成安装命令，也不内置 apt、yum、dnf 或数据库专用安装逻辑。
- 需要系统权限的环境组件必须显式声明 `requires_privilege`。框架在执行前检查 SSH 身份是否具备所需权限或可用的非交互 `sudo`；不支持运行中交互输入密码。
- 框架只区分两类由项目部署模块提供的敏感输入：`file_secrets` 表示 HTTPS/TLS 私钥、证书私钥或其他需要以文件形式部署的内容；`config_secrets` 表示数据库密码、令牌等按名称读取的配置值。框架不负责持久化、加密、生成或轮换这些输入。
- 项目部署模块在创建 CLI/运行器时绑定文件私钥名称到本地文件来源、配置密钥名称到值或延迟取值函数。集群 YAML 只引用这些逻辑名称，不包含真实秘密值；不同项目绑定保持实例隔离。
- `machines.yaml`、环境定义或 App 定义可声明文件私钥的目标机器、绝对目标路径、文件权限、可选属主/属组和覆盖策略。框架在相关配置脚本前通过 SSH 原子上传文件，应用限制性权限，并在计划和日志中仅显示逻辑名称与目标路径。
- 环境/App 的 Python 配置脚本显式声明所需 `config_secrets`。框架只把声明的配置密钥写入远端权限受限的临时脚本上下文，脚本通过标准上下文 API 按名称读取；上下文在脚本结束后无论成功失败均尝试删除。
- 标准上下文 API 提供模板渲染：模板中的 `$DB_PASSWORD` 和 `${DB_PASSWORD}` 从已声明的配置密钥中解析并替换，`$$` 表示字面量 `$`；未知、未声明或缺失的占位符直接失败。配置脚本也可直接读取 `context.config_secret("DB_PASSWORD")` 后自行生成应用配置。
- 配置密钥不进入远程命令参数、普通环境变量、执行计划或结果；文件私钥内容和配置密钥值不写入日志。框架对已绑定值执行统一脱敏，但项目脚本生成的最终应用配置及其权限由该脚本负责。
- 应用包元数据包含版本、必填的预期哈希，以及提供方特定的下载信息。框架定义可扩展的下载器/提供方接口；v0.1 实现 `http`/`https` URL 下载，并在部署脚本运行前进行流式哈希校验。
- 本地 Python 脚本文件被传输到临时远程工作目录，按配置的远程 Python 3 解释器（默认 `python3`）作为文件执行，使用有界的参数/环境上下文，执行后清理。在目标上执行第一个应用动作前检查解释器可用性。
- CLI 选择集群目录和动作，并提供可选的机器、机器环境实例、应用、执行器区域和地址类型过滤器/覆盖。全量集群部署逐机解析环境实例并按依赖顺序部署环境和 App；定向 App 部署默认仅校验环境依赖，显式使用 `--with-dependencies` 时才安装或更新其环境依赖。
- 项目部署模块导出的命令与框架通用命令使用同一套参数、校验、规划、执行和退出码语义；项目命令默认使用其绑定的配置根目录，同时允许通过显式参数选择该根目录下的集群。
- 在首次 SSH 连接前完成全面本地校验，确定性串行执行，目标内 fail-fast 行为，以及最终按主机/按应用的结果汇总。
- 针对配置验证和执行规划的自动化单元测试，以及使用可控 fake/test double 而不是生产主机的 SSH 边界测试。
- 包含配置和 CLI 示例的精简 README。

### 范围外
- 并行主机执行、滚动/金丝雀部署、基于仲裁或健康检查的编排。
- 清单发现、云厂商 API、容器/Kubernetes，或包/镜像构建。
- 除直接 HTTP/HTTPS URL 外的内置包提供方；其他项目通过下载器接口集成自己的提供方。
- 守护进程、调度器、Web UI、REST API 或远程控制面。
- 自动修改引用项目的 `pyproject.toml`、自动生成其部署模块，或在没有项目显式绑定的情况下扫描任意目录寻找集群配置。
- 框架内置数据库类型、数据库初始化业务规则、系统包管理器适配，或自动生成数据库账号、密码和业务 schema。
- 密码保险库、秘密加密存储、密码/密钥生成、版本管理、轮换、吊销、云厂商 Secret Manager 或 Vault 集成。
- 在命令参数、集群普通 YAML、日志或执行结果中保存/输出明文敏感值；运行远程部署脚本过程中交互输入 sudo 或应用密码。
- 自动创建数据库账号或修改数据库业务权限；框架只投递项目提供的文件私钥和配置密钥，不替代数据库自己的身份与权限管理。
- 自动回滚或推断回滚命令；操作员可以显式调用现有生命周期动作。
- 首个版本不支持 Windows 目标主机、Python 2、shell 生命周期脚本，或没有可用配置 Python 3 解释器的目标。

### 与相邻模块的边界
当前这是唯一的产品模块。该包拥有项目绑定 API、集群目录发现、配置解析与校验、环境/App 依赖排序、区域感知地址解析、包提供方抽象、内置 HTTP/HTTPS 检索、文件私钥投递、配置密钥上下文与模板替换、哈希校验、执行规划、权限预检、SSH 传输抽象、远程脚本生命周期、CLI 编排和结果报告。引用项目的部署模块拥有其集群配置根目录、项目命令注册、自定义下载提供方，以及文件私钥/配置密钥的真实来源；用户拥有的环境与应用 Python 脚本负责数据库等具体软件的安装、配置和业务语义。

## Requirement Review
修订后的目录模型合理，让每个集群都成为可移植、可评审的单元。将 `cluster.yaml`、`machines.yaml` 和 `apps/<app-name>/` 分开，使拓扑、放置、包身份和应用特定脚本保持独立，而不在集群间强制全局定义。

数据库等基础软件与业务 App 的生命周期和风险不同，因此环境使用独立的 `environments/<environment-name>/` Python 脚本定义，而实际环境实例归属 `machines.yaml` 中的具体机器。这个“脚本复用、机器实例化”模型既避免重复复制 PostgreSQL 等安装脚本，也保证版本、端口、数据目录和权限等最终配置由机器拥有。机器配置是脚本输入，不是声明式安装器；PostgreSQL、MySQL、Redis 或语言运行时的具体检查、安装、配置和服务控制全部由项目 Python 脚本实现。框架只提供实例解析、依赖排序、脚本传输与调用、权限预检和结果判定。`check` 前置动作提供最小幂等契约，但框架不声称任意用户脚本天然幂等。

定向部署不能静默修改依赖环境，因此默认只验证依赖是否满足，只有全量集群部署或显式 `--with-dependencies` 才执行依赖安装。这让便利性与远程副作用保持可见。

区域感知寻址需要显式比较点。所选方向将部署执行器/源区域作为集群配置并可由 CLI 覆盖，然后应用请求的同区域/私有、跨区域/公网规则。这避免了从网络接口或 DNS 猜测执行器区域。地址类型覆盖在异常路由时保持显式，而缺少默认路由地址时则失败关闭。

包哈希校验是必须的，因为 URL 标识从何处获取工件，但不标识受信任的工件。下载提供方接口接受类型化的提供方特定密钥信息，并产生本地校验后的工件；脚本不会收到未校验的包。v0.1 仅包含 HTTP/HTTPS URL，而自定义项目可以在不改变集群或执行编排的情况下添加提供方。

项目集成采用显式绑定而不是约定式全局扫描。框架提供可复用 CLI 构建函数，项目部署模块以绝对、模块相对解析后的配置根路径调用它，并把所得入口导出为 console script 或 `python -m <project-deploy-module>` 的 `main`。这只需要薄包装层，同时让项目安装位置、当前工作目录和多个项目之间保持隔离。框架通用 CLI 仍可用于显式传入配置根目录的独立调用。

敏感数据能力采用“项目提供、集群引用、框架投递”的窄边界。文件私钥作为文件部署到声明的机器路径；配置密钥仅在配置脚本运行期间通过受限上下文提供，并可用于 `$NAME`/`${NAME}` 模板替换。框架不成为秘密存储系统，项目可自行从文件、环境、CI 或外部系统取得真实值后绑定给部署模块。这个方向满足部署需要，同时避免首版承担保险库、主密钥和轮换协议。

主要权衡是安全与初始吞吐量。串行执行是 v0.1 的刻意选择，因为远程副作用、输出顺序和失败归因保持确定性。一旦取消、部分失败和重试语义有了自己的批准设计，后续任务可以增加有界并发。

SSH 安全依赖严格 known-host 数据库以及 SSH agent 或明确的本地私钥路径。框架不会静默接受未知主机密钥，也不会将敏感值或不受信任的配置值拼接进远程命令。Python 脚本路径、解释器路径、动作名称、参数和环境键在本地校验；传输和命令构造被隔离在类型化接口后面，便于聚焦测试。

## Success Criteria
- 具体用户可见或系统可见结果：项目部署模块引用框架并绑定项目内集群目录、文件私钥和配置密钥后，操作员可从任意工作目录直接调用项目命令，按机器部署环境和 App，将 HTTPS 等私钥文件投递到声明路径，并由 Python 配置脚本读取 `DB_PASSWORD` 等配置密钥或替换模板中的 `$DB_PASSWORD` 来生成应用配置。
- 必需证据：包构建/导入检查、示例项目部署模块及其导出命令测试、任意工作目录和多项目绑定隔离测试、环境模板/机器实例/App 引用校验、文件私钥投递与配置密钥上下文/模板替换测试、机器级覆盖和多实例隔离测试、依赖图与顺序测试、环境状态检查和权限预检测试、仅 Python 脚本校验和解释器预检测试、地址解析测试、下载器/提供方和哈希校验测试、执行规划单元测试、mock/fake SSH 成功与失败测试，以及使用 fake/test 传输或测试 SSH 端点的已记录本地演示。
- 显式非目标：并发、滚动升级、自动回滚、秘密保险库及轮换系统、非 POSIX 目标、服务器/API/UI 模式，以及与外部基础设施平台的集成。

## Risks
- 远程脚本拥有 SSH 账号授予的任意权限；框架必须使目标和动作明确，且不得扩大该权限边界。
- 不正确的主机密钥行为可能导致机器冒充；未知或变更的密钥必须默认失败关闭。
- Shell 引号或不安全的变量插值可能导致命令注入；执行必须使用固定远程启动器构造和有界、校验的上下文。
- 远程 Python 解释器路径和脚本参数也是命令边界输入；它们必须表示为校验后的参数并正确引号，而不是插值为自由格式命令文本。
- 失败可能使远程应用部分变更。v0.1 报告精确的失败步骤并在该目标上停止后续脚本，但不声称事务性部署或自动回滚。
- 配置和 CLI 形态成为项目的第一个公开契约；兼容性决策必须在实现前的设计中显式说明。
- `create_cli(...)`、`run(...)`、下载提供方注册协议和命令退出码成为引用项目依赖的公开接口；设计必须隔离每个项目绑定的状态并避免进程级可变注册表泄漏。
- 错误或缺失的执行器区域数据可能选择不可达或非预期的网络路径；路由输入和覆盖必须在执行计划中可见，并在不完整时失败关闭。
- 包 URL 可能重定向、超时、耗尽磁盘/内存或返回变更内容；HTTP 检索需要有界流式行为、显式超时/重定向策略、临时文件清理和强制哈希校验。
- 自定义包提供方是可执行扩展代码。接口和注册边界不得暗示不受信任的提供方配置本身被沙箱化。
- 文件私钥若投递到错误机器、路径或权限不当会造成严重泄露；目标机器、绝对路径、覆盖策略、属主和限制性权限必须在首次 SSH 副作用前完成校验，上传采用同目录临时文件后原子替换。
- 将配置密钥传给远程 Python 脚本会扩大该脚本的信任范围；每个动作必须声明所需名称，只投递该集合，并在失败与取消路径同样清理临时上下文。清理不能撤销已被脚本写入最终配置或复制的秘密。
- `$NAME` 替换若使用 Shell 展开语义会引入歧义和注入；框架只实现固定标识符替换、`${NAME}` 形式和 `$$` 转义，未知或未声明变量失败，不执行命令替换或其他 Shell 表达式。
- 数据库安装通常需要高权限并会产生持久数据与系统服务。权限必须在副作用前完成预检；失败停止依赖链；停止、重启或重新部署环境组件不得暗示会删除数据。
- 错误的机器级环境实例或跨机器依赖可能导致错误目标、错误顺序或循环；模板引用、实例唯一性和完整依赖图必须在首次 SSH 连接前校验，并在执行计划中显示每一步的机器/实例身份和最终拓扑顺序。
