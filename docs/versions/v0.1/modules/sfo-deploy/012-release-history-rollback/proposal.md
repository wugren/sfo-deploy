# sfo-deploy 发布历史与指定版本回退提案

Risk profile: ./risk-profile.yaml

- Final tier: high-risk

  CLI，并直接改变部署、兼容性与回退行为；失败或不完整的快照可能导致集群恢复到错误状态，因此同时触发
  data、contract、runtime、deployment/rollback 风险边界。
- Proposal and tier confirmation: 用户已确认提案与 high-risk
  层级，并明确“流量发布记录”指“浏览发布记录”；用户原文“确认，这里指浏览发布记录，自动完成”同时启动从

## Background and Goal

当前 sfo-deploy
会根据集群目录中的即时配置规划并执行部署，但部署结束后不保存可查询的发布历史，也不能从历史输入重建某个已成功发布的集群版本。目标是让发布过程形成可审计、可枚举的历史，并允许操作人员选中一个成功发布版本执行确定性的回退。

## Scope

### In scope

- 每次 App `deploy` 调用都生成唯一、稳定的集群发布 ID，并记录开始时间、结束时间、调用选择范围、App
  版本、目标机器、最终状态以及脱敏后的步骤结果；失败和取消的尝试也保留审计记录。
- 成功发布原子地保存足以再次执行该发布的不可变快照，包括已校验的相关 App
  配置、脚本、模板、包来源与内容哈希，以及重建目标选择所需的集群/机器信息；快照不得包含配置密钥值、私钥内容或临时下载凭据。
- 新增发布历史查询能力：按集群列出发布记录，并查看单条记录；默认采用机器可读 JSON 输出，延续现有 CLI
  输出约定。
- 新增按发布 ID 回退能力。只有状态为成功且快照完整、可校验的发布可以成为回退目标；回退在任何 SSH
  或远端副作用前完成历史存在性、快照完整性、哈希、目标与本地绑定预检。
- 回退复用现有规划、下载、传输、执行、结果脱敏和稳定退出码边界，并为回退本身新增一条关联原发布 ID
  的历史记录，避免丢失审计链。
- 定义历史存储的原子写入、并发冲突、损坏记录、缺失快照、部分部署失败和回退失败语义，并提供对应测试与用户文档。

### Out of scope

- 不实现负载均衡器、网关权重、灰度发布、蓝绿发布或自动流量切换。
- 不把发布历史同步到远端数据库、云服务或多操作端共享存储；首版历史归属当前集群目录的本地持久化状态。
- 不回滚数据库内容、环境安装、外部服务状态，亦不承诺撤销 App 脚本已经造成的不可逆副作用。
- 不允许失败、取消、被篡改或快照不完整的发布成为回退目标。
- 不以 `app.yaml` 中可能重复的 App `version` 直接替代唯一发布 ID。

### Boundary with neighboring modules

- 配置加载仍负责当前集群配置的严格校验；历史模块只读取由发布流程生成并校验过的版本化记录与快照。
- 规划器继续输出不可变执行计划；历史恢复负责从快照重建等价输入，再交由现有执行器执行。
- 下载 provider、SSH transport、密钥绑定与远端脚本接口保持原职责，不由历史存储接管。
- CLI 负责参数与 JSON 序列化，持久化、校验和恢复语义由独立领域接口承担，便于项目绑定 API 与 CLI
  共用。

## Requirement Review

- 需求合理：没有发布历史就无法审计实际部署，也无法可靠定位回退目标；仅把当前 `app.yaml`
  的版本字段改回旧值不足以复现旧脚本、模板和包引用。
- 选择“唯一发布 ID + 不可变快照 + 追加式审计记录”，而不是只记 App 版本字符串。这样可以处理同一 App
  版本重复发布、定向机器发布和配置文件后续变化。
- “每次发布”解释为每次 App `deploy`
  尝试；尝试无论成功、失败或取消都记入历史，但只有完整成功记录可回退。
- 回退不是把历史指针改成旧值，而是基于历史快照执行一次新的部署；新动作也形成记录并关联来源，以保留完整因果链。
- 当前把用户原文“能够流量发布记录”理解为“能够浏览发布记录”。若实际要求是记录或控制灰度流量、网关权重，则需要扩展外部系统契约和状态模型，必须先修订本提案。

## Success Criteria

- Concrete user-visible or system-visible result:
  操作人员能列出某集群的发布历史、查看唯一发布记录，并选择一个成功发布 ID 将对应
  App/机器范围重新部署为当时的已校验版本；输出中能追踪本次回退与原发布的关联。
- Required evidence: 数据格式与兼容性设计、原子/并发/损坏恢复设计、CLI/API
  正反契约测试、无秘密持久化证明、成功及失败工作流测试，以及独立验收中的指定版本回退反例检查。
- Explicit non-goals: 不包含流量治理、数据库回滚、远端历史服务、自动保留期清理或跨集群回退。

## Risks

- 发布历史是新的持久化数据格式，需要 schema
  版本、向后读取策略、损坏隔离和原子提交语义；实现不能让半写入记录被识别为可回退版本。
- 回退会执行真实远端副作用；在历史、快照、哈希、本地密钥/provider 或目标解析不完整时必须在首次 SSH
  前失败。
- 定向发布可能只覆盖集群子集，因此记录必须精确绑定
  App、机器和依赖范围，不能把部分范围误报为完整集群快照。
- 历史和命令输出必须严格脱敏，不能复制配置密钥值、文件私钥、provider 凭据或临时路径中的敏感内容。
- 同一集群的并发发布/回退若不串行化或做冲突检测，可能产生重复
  ID、错误先后关系或与实际状态不一致的历史。
- 已确认：用户原文“流量发布记录”意为“浏览发布记录”，不包含流量权重或灰度切换。
