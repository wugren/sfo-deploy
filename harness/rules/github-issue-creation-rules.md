# GitHub Issue Creation Rules

Applies to issue creation/submission in every tier. Drafting is preparation; the GitHub create call requires confirmation of the exact final submission.

## Confirmation and Submission
1. Prepare and display the target owner/repository, title, complete body, and all submission metadata (labels, assignees, milestone, project placement, etc.; use `none` where absent).
2. Ask for explicit current-user confirmation and wait. Never submit in the turn that first displays a new or revised draft, even if the user requested immediate submission or skipped review.
3. Accept only unambiguous approval of that displayed submission. Silence, inferred intent, the original creation request, another artifact's approval, agents, automation, and prior conversations do not count.
4. Any field change invalidates confirmation: display the complete revised draft and obtain confirmation again.
5. Submit exactly the confirmed content and metadata, then report the issue number and URL. On failure, report it; do not silently alter the draft for a retry.

Confirmation covers one issue only. Multiple issues need separate complete drafts and confirmations; clarification and draft review do not authorize submission.
